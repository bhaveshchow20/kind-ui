## Usage

Set `categoryKey` for stable slice colors and `innerRadius` for a donut.

```tsx title="Composition"
<Chart.Root config={config}>
  <Chart.Legend />
  <Chart.ResponsiveContainer width="100%" height={280}>
    <Chart.PieChart animate accessibilityLayer aria-label="Team allocation">
      <Chart.PieSeries data={data} dataKey="hours" categoryKey="key" nameKey="key" innerRadius={58} outerRadius={108}>
        <Chart.LabelList dataKey="share" position="inside" fill="white" stroke="none" style={{ fill: "white", fontWeight: 600 }} />
      </Chart.PieSeries>
      <Chart.Tooltip itemKey={(entry) => String(entry.payload?.key ?? entry.name)} />
    </Chart.PieChart>
  </Chart.ResponsiveContainer>
</Chart.Root>
```

Use stable keys for config, `categoryKey`, `nameKey` and `Tooltip.itemKey`. Reordering rows preserves their configured colors. Pie has no configured wrapper or separate Donut export.

Chart-owned angular entrance respects reduced motion. `animationDirection` changes the sweep, preserving final angles and data order.

## Controlled categories

Toggle categories in the legend; the selected total updates with the visible slices.

For shared slice and legend actions, use `interactionBinding="root"` and category interaction. This example also shows an initial tooltip, selective glow and a loading state.

<ChartExample id="pie-interaction" />

<details>
<summary>Category interaction contract</summary>

Supply complete rows, unique nonempty string IDs and a settled `eligibleKeys` list, including hidden and zero-valued categories. Root binding filters rows and positional Cells together. Without binding, filter rows in consumer state; `visibleSeries` alone cannot hide Pie rows. Remaining slices use the selected total.

`markActivation="matching-legend"` shares visibility or focus actions between slices and legend buttons. Focus highlights without filtering. Enter/Space activates; Escape resets. Consumer handlers run first and may veto with `preventDefault()`; `interaction.onBeforeInteraction` can also veto. Actions use committed state and the original pressed row identity, even if a handler reorders data. Cell paint/payload overrides and custom rendering remain consumer-owned. Keep a legend or explicit accessible controls. The legend rejects hiding the final eligible category with a scoped announcement; explicit controls may set an empty selection.

</details>

## Initial tooltip

Set `defaultPinnedCategory="service"` to open the first tooltip on Service. It follows that ID when rows reorder.

<details>
<summary>Initial tooltip requirements and dismissal</summary>

Use one direct PieSeries with explicit rows and `categoryKey`, and one direct Tooltip with `itemKey`; Fragments are allowed. Multiple series or other direct children are unsupported. Bound charts locate the pin among visible rows; unbound charts use consumer-rendered indices. Hiding/removing the identity, pointer activity, focus or a key press dismisses the pin permanently until remount. Unknown IDs never pin; ambiguous duplicates clear unbound pins, while Root binding rejects duplicate IDs. Restoring a row or changing the default does not repin. Explicit Tooltip `active` and `defaultIndex` retain control. Pins do not change Root focus or selective glow.

</details>

## Loading

Choose Loading in the example above. `loading` preserves layout, blocks inspection and announces `loadingLabel`. Empty data is a separate state; provide an empty-result message.

## Materials

Start with Default (`plain`), then switch to Clay or Glow. Percentage labels stay inside; category names stay in the legend.

<ChartExample id="pie-materials" />

### Selective glow

Use `glowCategories={["design"]}` to give Design a halo. IDs remain stable through reorder and filtering. Unknown IDs are ignored; an empty list keeps the series material. `material="glow"` applies glow to every default sector.

```tsx title="Selected category on a rounded donut"
<Chart.PieSeries
  data={data}
  dataKey="hours"
  categoryKey="key"
  nameKey="key"
  innerRadius={58}
  outerRadius={108}
  cornerRadius={8}
  paddingAngle={2}
  material="plain"
  glowCategories={["design"]}
/>
```

Glow is decoration, not selection state. Keep category labels and a data table; preserve readable native fills in each theme. Native Cell/datum paint, custom shapes, active shapes, filters and CSS transform ownership still take precedence. `categoryKey` requires explicit data and configured string IDs even when a native fill is supplied.

## Rounded and petal sectors

`cornerRadius` and `paddingAngle` are existing native `PieSeries` props. Use a small radius and gap for rounded sectors, or half the ring thickness with a larger gap for a petal-like donut. No separate Donut component or custom shape is needed.

<ChartExample id="pie-rounded" />

Switch Geometry to compare the same data. Rounded donut uses `cornerRadius={8}` and `paddingAngle={2}`; petal donut uses `cornerRadius={20}` and `paddingAngle={8}`. The table keeps original hours and shares.

<details>
<summary>Geometry constraints</summary>

Use finite, nonnegative values and radii with `0 <= innerRadius < outerRadius`. Numeric corner radii are SVG units; native sectors clamp rounding to half the ring thickness and may fall back to ordinary corners when a narrow sector cannot fit the requested rounding. Full-circle sectors do not show rounded ends. The petal silhouette depends on the data proportions and available sector angles; it is not a guarantee for every dataset.

Angles and padding are degrees. Native Pie caps the absolute sweep at 360 degrees; equal start/end angles paint no allocation. For `n` positive categories, a full circle reserves `n * paddingAngle`, while a partial sweep reserves `(n - 1) * paddingAngle`. Keep nonnegative padding small enough that this total is strictly below the sweep, and leave `minAngle` at zero for these proportional recipes. Re-evaluate spacing after filtering or changing the data. Native Pie ignores padding for a single supplied row; zero values have no visible share. Keep zero categories in the data alternative, and do not enlarge them to create petals.

These examples render final geometry with `animate={false}`. If entrance animation is enabled, Kind's existing reduced-motion and custom-shape ownership contracts still apply.

</details>

## API reference

Focused props for explicit Pie composition; upstream links cover native options.

### PieChart

Use inside a sized `ResponsiveContainer`.

<div className="line-props-scroll" role="region" aria-label="PieChart props" tabIndex={0}>

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `animate` | `boolean \| PieAnimation` | `false` | Sector entrance and interaction motion; respects reduced motion. |
| `animationDirection` | `"clockwise" \| "anticlockwise"` | `"clockwise"` | Continuous entrance sweep; native geometry and row order stay unchanged. |
| `defaultPinnedCategory` | `string` | Off | Initial category tooltip; requires one direct category-keyed PieSeries and one Tooltip. Dismissal is permanent until remount. |
| `loading` | `boolean` | `false` | Explicit pending state with a chart-owned loading illustration and blocked inspection. |
| `loadingLabel` | `string` | `"Loading chart"` | Accessible pending status. |
| `accessibilityLayer` | `boolean` | `true` in Recharts | Enables native keyboard inspection; set explicitly here. |
| `aria-label` / `aria-labelledby` | `string` | — | Accessible chart name. |
| `children` | `ReactNode` | — | Explicit PieSeries, labels and tooltip. |

</div>

`PieAnimation` accepts `revealDurationMs` (default `1000`), `revealEasing` and `hoverTransition`. Changing these or direction during entrance finishes it. Per-series animation is disabled. See [Recharts PieChart](https://recharts.github.io/en-US/api/PieChart/).

### PieSeries

Value and category identity use separate fields.

<div className="line-props-scroll" role="region" aria-label="PieSeries props" tabIndex={0}>

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `data` | `Row[]` | — | Consumer-owned category rows. |
| `dataKey` | `string \| number \| ((row: Row) => unknown)` | `"value"` in Recharts | Numeric value field or accessor; set explicitly here. |
| `categoryKey` | `string \| ((row: Row) => string)` | Off | Resolves an own top-level field or accessor into `Root.config`; requires explicit series data and string IDs. |
| `interactionBinding` | `"root"` | Off | Shares category identities with category-kind Root interaction; filters original rows and Cells using Root visibility. |
| `nameKey` | `string \| number \| ((row: Row) => unknown)` | `"name"` | Native category name; use config keys for semantic identity. |
| `innerRadius` | `number` or percentage | `0` | A positive radius produces a Donut. |
| `outerRadius` | `number` or percentage | `"80%"` | Sector size; percentages use Recharts' available radius. |
| `startAngle` / `endAngle` | `number` | `0` / `360` | Native angular geometry in degrees. |
| `paddingAngle` | `number` | `0` | Native gap in degrees; see geometry constraints above. |
| `cornerRadius` | `number \| string` | `0` | Native rounded sector corners; numeric units are recommended here. |
| `material` | `"plain" \| "clay" \| "glow"` | `"plain"` | Finish on default sectors; consumer rendering can take precedence. |
| `glowCategories` | `readonly string[]` | Off | Category IDs receiving glow instead of `material`; requires `categoryKey` and explicit data. Unknown IDs are ignored. |
| `emphasisKey` | `(payload: unknown) => string \| number \| undefined` | Native name | Optional semantic sector identity for paint emphasis; does not configure tooltip identity. |
| `stroke` | `string` | `"none"` | Native sector outline. |

</div>

Explicit series fill disables category defaults; datum or Cell fill wins over them. Custom shapes retain rendering control. Choose consumer row filtering or explicit Root binding; `PieSeries` has no `seriesKey`. Custom shapes, filters or transforms can bypass Kind paint. See [Recharts Pie](https://recharts.github.io/en-US/api/Pie/).
