## Usage

Area describes a nonnegative amount. Color describes a separate metric. In the primary example, choose Signed return or Activity to change color while capitalization area stays unchanged. The complete example also accepts `areaMetric="turnover"` when that is the intended weight.

```tsx title="Composition sketch"
import { TreemapChart } from "@kind-ui/charts";

<TreemapChart
  data={data} accessors={accessors} encoding={encoding}
  config={{}} aria-label="Allocation and independent change metric"
  height={320} padding={3} groupHeaderHeight={22}
>
  <TreemapChart.Groups />
  <TreemapChart.Tiles />
  <TreemapChart.Labels minWidth={46} minHeight={24} />
  <TreemapChart.Tooltip />
  <TreemapChart.ColorLegend />
  <TreemapChart.Breadcrumbs />
</TreemapChart>
```

Examples contain the graph and its readouts; the documented plotted values below each example provide its data alternative. For an application, compose `TreemapChart.DataTable` with a caption or supply a navigable alternative in `Content`.

## Hierarchy, missing values and shares

The standard `TreemapDatum` shape is `{ kind: "leaf", id, label, value }` or `{ kind: "group", id, label, children }`. Custom records use `TreemapAccessors<T>` for ID, label, children and leaf area. Undefined children identify a leaf; an explicit empty array identifies an empty group. The value accessor runs only for leaves. Groups derive their area from descendants and cannot supply a separate standard `value`.

IDs must be globally unique, stable and nonempty. Labels must be nonempty and can repeat. Areas must be finite and nonnegative; missing area needs an explicit adapter policy. Invalid children, cycles, shared records and overflowing totals throw errors with hierarchy locations. Zero leaves stay in semantic data without visible area. Missing color is separate from numerical zero.

Normalized nodes retain `datum`, `kind`, `parentId`, zero-based `depth`, an ID `path` and derived `value`. `rootShare` uses the entire supplied forest after application filtering. `parentShare` uses the parent total, or the forest total for roots. `viewShare` uses the current subtree total and is null outside that subtree. Zero denominators produce `null`. External market universes, NAV and other accounting denominators remain application metadata.

## Navigation, selection and loading

Group headers and frontier tiles are buttons. Enter/Space selects an item and opens groups; arrows and Home/End move among rendered controls. Hover or focus changes transient inspection without changing totals. Escape dismisses the tooltip. Breadcrumb buttons return to surviving ancestors or the full forest.

Control subtree state with `viewId` and `onViewChange`, inspection with `activeId` and `onActiveChange`, and persistent selection with `selectedId` and `onSelectionChange`. Use `defaultViewId`, `defaultActiveId` or `defaultSelectedId` for uncontrolled initial state. When an item disappears, its nearest surviving ancestor is used, followed by the forest root (`null`). Callbacks receive original records with `rectangle` (or null when not rendered) and `viewShare`.

`layout="stable"` retains layout rows across weight and size changes while subtree view and hierarchy membership remain unchanged. Membership changes, regrouping or a different view invalidate that cache. IDs preserve identity, not fixed positions. `layout="squarify"` recomputes rows. Tiny labels are omitted below `minWidth`/`minHeight` thresholds and clipped inside cells; small observations remain in the data alternative.

`animate` is opt-in and respects reduced motion. Set `loading` while data is pending and provide `loadingLabel` for its status. Applications own fetch cancellation, retries and filtering.

## Color encoding

`encoding` supports categorical, sequential, zero-centered diverging, threshold and custom modes. The resolved encoding supplies both tiles and `ColorLegend`; root config does not calculate color metrics. Omitting encoding uses categorical root-group colors.

Continuous encodings use a fixed `domain` or infer one from available metrics in `domainScope="root"` (default) or `"view"`. Diverging inferred domains are symmetric around zero; explicit diverging domains must contain zero. Equal endpoints use the midpoint paint. Paint clamps outliers without altering readouts. Threshold boundaries enter the upper band. Use ascending finite thresholds and one more color than thresholds.

`unknownColor` and `unknownLabel` describe missing/nonfinite metrics. Groups use `groupValue` or an explicit numeric `aggregate` callback; these policies are mutually exclusive. Core does not average leaf returns or invent group P&L. Caller formatters define units and distinguish percent from percentage points.

## API reference

Treemap uses React-owned HTML marks and a narrow `d3-hierarchy` layout dependency. It takes the owning `TreemapChart` directly, with explicit parts. Native Treemap props and nested `.Root`/`.Plot` APIs do not apply.

### TreemapChart

<ApiTable name="TreemapRootReference" />

Pass a named chart, `config` and explicit children. Custom data requires `accessors`; standard data does not. Plot height defaults to 280px, `padding` to 2, `groupHeaderHeight` to 20, and `layout` to `"stable"`. `animate` and `loading` default to false; `empty` defaults to `"No positive values"`. Controlled state and its corresponding `default*Id` are mutually exclusive.

Keep custom tile/header presentation free of nested buttons. Parts retain `className`, `style`, native handlers and refs. Specify the custom record type on generic content callbacks when needed, such as `<TreemapChart.Tooltip<StorageRecord>>`.

### Pure model and color resolution

`normalizeTreemap(data, accessors?)` returns roots, preorder nodes, `byId` and total; the no-accessor overload accepts only `TreemapDatum`. `resolveTreemapColors(nodes, viewNodes, encoding)` returns ID-keyed readouts and a legend. These helpers do not fetch data or calculate application financial metrics.
