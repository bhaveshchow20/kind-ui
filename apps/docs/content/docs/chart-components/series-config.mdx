title: SeriesConfig
description: Define labels, colors and value formatting for chart series.
---

`SeriesConfig` maps stable series or category keys to labels, colors and optional formatting. Pass it to [Root](/docs/chart-components/root/) or directly to a configured [LineChart](/docs/components/line/).

## Usage

```tsx title="config.ts"
import type { SeriesConfig } from "@kind-ui/charts";

export const config = {
  visitors: {
    label: "Visitors",
    color: "#733bff",
    formatValue: (value) =>
      typeof value === "number" ? value.toLocaleString("en-US") : String(value),
  },
  subscribers: {
    label: "Subscribers",
    color: "#1c9d8f",
  },
} satisfies SeriesConfig;
```

Use the same keys in `dataKey` or `seriesKey`. For category charts, match the category identity instead of the measured value. See [Identity and colors](/docs/concepts/identity/) for accessor and category examples.

Keys must start with a letter and contain only letters, numbers, underscores or hyphens. `Root` exposes each color as `--color-<key>`; for example, `var(--color-visitors)`.

## Metadata

Each config entry has the following fields:

<ApiTable name="SeriesMetadata" />

- `label` is optional and appears in the built-in legend, tooltip and built-in accessible series text. An explicit label takes precedence, including an empty string. When omitted, `visitors` infers `Visitors` and `monthlyVisitors` infers `Monthly visitors`. Camel-case and acronym boundaries, underscores and hyphens become spaces; words are lowercased and the first letter is capitalized. Provide a label for custom wording or casing. Configuration keys must match the series data keys (or explicit `seriesKey`); category charts use their category identity. Inference does not change keys or colors.
- `color` supplies the default series color and marker color. Explicit series paint takes precedence.
- `icon` supplies a decorative React component for the legend and tooltip.
- `legendShape` selects a Recharts symbol for the legend. A configured icon takes precedence; use the same shape on `ScatterSeries` when its marks should match.
- `formatValue` formats non-null tooltip values and returns a React node. A tooltip or payload formatter takes precedence.

The legend follows config insertion order. Config describes presentation; chart data and visibility remain separate.

## Theme colors and series patterns

Colors also accept gradient stops or complete light/dark definitions. Configured patterns supply implicit Bar/Area fills and default legend swatches. See the validation and defaults below; [Bar patterns](/docs/components/bar/#series-patterns-and-projected-bars) covers native paint precedence.

## Labels, theme colors and diagnostics

`SeriesConfig[key].label` is optional. `monthlyVisitors` infers “Monthly visitors”; explicit text, including `""`, wins. Identity keys stay unchanged. [SeriesConfig](/docs/chart-components/series-config/) describes matching, icons, legend symbols and formatter precedence.

`color` accepts a CSS string, an array of gradient stops, or `{ light, dark }` theme values. Set CSS `color-scheme` on the host.

`--color-key` exposes the first stop; chart-local SVG resources provide the full gradient. Native paint and custom renderers retain precedence.

<details>
<summary>Color validation and resource identity</summary>

Gradient arrays require nonempty, evenly spaced stops. Each theme can use a string or array; unequal stop counts retain their spacing.

Empty strings, arrays or invalid theme shapes throw with the config key, theme and stop index where applicable. CSS syntax and contrast remain consumer-owned. Independent React roots require distinct SSR/hydration `identifierPrefix` values.

</details>

Development builds warn once when the stylesheet marker is missing after mount, including hydration and delayed stylesheet loading. Production does not run that diagnostic. Import the stylesheet instead of suppressing the warning; explicitly styled consumers still own their CSS.
