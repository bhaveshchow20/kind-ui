title: Root

`Root` connects your plot, legend and tooltip to a [series config](/docs/chart-components/series-config/).

## Usage

```tsx
import * as Chart from "@kind-ui/charts";

const config = {
  orders: { label: "Orders", color: "#4477aa" },
} satisfies Chart.SeriesConfig;

<Chart.Root config={config}>
  <Chart.Legend />
  <Chart.ResponsiveContainer width="100%" height={280}>
    <Chart.BarChart data={[{ day: "Mon", orders: 24 }]} aria-label="Daily orders">
      <Chart.XAxis dataKey="day" />
      <Chart.BarSeries dataKey="orders" />
      <Chart.Tooltip />
    </Chart.BarChart>
  </Chart.ResponsiveContainer>
</Chart.Root>
```

## Visibility

Pass `visibleSeries` to control visibility in your own state. Add `onVisibleSeriesChange` to receive [Legend](/docs/chart-components/legend/) requests; without it, controlled visibility is read-only unless you configure focus interaction.

```tsx
import { useState } from "react";

const [visibleSeries, setVisibleSeries] = useState<string[]>(Object.keys(config));

<Chart.Root
  config={config}
  visibleSeries={visibleSeries}
  onVisibleSeriesChange={setVisibleSeries}
>
  {/* Legend and plot */}
</Chart.Root>
```

For Root-owned visibility, pass `defaultVisibleSeries`. Root updates this initial selection internally; an optional `onVisibleSeriesChange` observes accepted changes. Choose `visibleSeries` or `defaultVisibleSeries`, never both. A visibility callback requires one of these arrays.

```tsx
<Chart.Root config={config} defaultVisibleSeries={Object.keys(config)}>
  <Chart.Legend />
  {/* Legend and plot share Root-owned visibility */}
</Chart.Root>
```

Series adapters consume this visibility. An unbound [PieSeries](/docs/components/pie/) keeps consumer-owned row filtering; opt into its category binding to let Root filter rows and Cells together.

Legend requests cannot hide the final visible eligible item. Root preserves visibility and announces “At least one item must remain visible.” An external controlled update may still set `visibleSeries={[]}`; your data alternative and empty-result message remain consumer-owned.

## Interaction and eligibility

Set the identity kind and settled `eligibleKeys` through `interaction`. Include Root-hidden items and zero values; exclude unavailable identities. Keep IDs stable across reorder. Native adapters also report availability.

Without a snapshot, Root uses registered identities or, if none exist, config keys.

Eligible legend items can be controls. Unavailable items retain labels without toggle buttons; Root-hidden items remain restorable.

Empty data or native `hide` does not write a new visibility array or call the visibility callback. Availability changes do not invoke controlled selection callbacks.

`mode="visibility"` is the default. `mode="focus"` highlights an identity without filtering data. Use `kind="series"` for native series, `"category"` for bound Pie categories, or `"node"` for node focus; node interaction supports focus only.

```tsx
<Chart.Root
  config={config}
  interaction={{
    kind: "series",
    mode: "focus",
    eligibleKeys: Object.keys(config),
    defaultSelected: null,
    markActivation: "matching-legend",
  }}
>
  <Chart.Legend />
  {/* Participating marks and legend share focus */}
</Chart.Root>
```

Control focus with `selected` and required `onSelectionChange`, or initialize it with `defaultSelected` and an optional callback. Do not combine these modes or change ownership while mounted.

Activating the selected identity clears it; Escape requests a focus reset. Root announces accepted focus and visibility changes in a scoped live region.

`markActivation="matching-legend"` opts participating native marks into the same actions; shared mark actions default off.

Consumer handlers run first. `event.preventDefault()` or `interaction.onBeforeInteraction(request)` returning `false` vetoes the action, including Escape reset. A request supplies its identity (or `null` for reset), source, mode and original event.

Actions use committed state/callbacks, including after synchronous consumer updates.

## Loading

All 13 chart families and ActivityRings accept `loading` and `loadingLabel`. While loading, the chart keeps its dimensions, shows a decorative silhouette, hides/inerts managed content and announces the label outside busy content.

The label defaults to “Loading chart”. Reduced motion keeps the silhouette static.

Omitted loading preserves the chart. `false` restores data, including empty datasets, and runs enabled entrances. Repeated interruptions retain dimensions. External legends and custom content remain consumer-owned.

Derive loading from request state; supply error/empty messages, cancellation and retry. The illustration represents neither partial values nor completion.
