Kind UI is pre-release and unpublished. Release work in [PR102](https://github.com/bhaveshchow20/kind-ui/pull/102) keeps publishing disabled. These docs consume a retained `0.1.0` candidate from <PackageSource />, including the integrated APIs and Heatmap dismissal correction. A candidate version or passing CI does not establish npm availability.

## Reproduce this preview

The served [provenance JSON](/package-provenance.json) records source commit, SHA-256 and npm integrity. Use the [setup files](/examples/line/README.md), lockfile and [pinned tarball](/examples/package/kind-ui-charts-0.1.0.tgz) together. Follow [installation](/docs/start/installation/); a version alone does not distinguish candidate builds.

This pin includes category/Sankey metadata defaults, compact Heatmap layout and ActivityRings. Their [component examples](/docs/guides/candidate-apis/) use the same integrated artifact. Glass remains paused.

## Validate the final candidate

The release owner supplied the exact integrated package and provenance for this pin. Any further source or manifest change requires a new package gate and retained tarball. Compare the tested bytes' checksum with the receipt; do not substitute a repack. Update the docs pin, app/consumer lockfiles and generated setup together, then rerun strict copied consumers, source/Code/Copy parity, docs build, links and focused browser checks.

The packed-package gate proves ESM imports and strict NodeNext/Bundler declarations at pinned peers. Framework integration and browser support need their corresponding test evidence. Candidate branch checks do not prove the final integrated artifact, registry installation, every browser or manual assistive-technology use.

## After registry verification

Only show a registry install command after verifying the exact public package/version and matching integrity against the tested release receipt. Record the published version, source commit and registry provenance, then verify the documented install in a clean consumer. Preserve exact-version instructions and the supported peer/test boundary. Until then, use the local-artifact path above.

Publication, deployment and merging remain separate owner actions. See the source snapshot's [contribution workflow](https://github.com/bhaveshchow20/kind-ui/blob/d66ad717eaa0220b83b60de9420c94b65d67118c/CONTRIBUTING.md) and [development policy](https://github.com/bhaveshchow20/kind-ui/blob/d66ad717eaa0220b83b60de9420c94b65d67118c/docs/development.md).
