Use the same source that drives the chart preview. Start with the relevant family instead of loading the entire documentation set.

<Steps>
<Step>

### Add the consumer skill

```sh
npx skills add bhaveshchow20/kind-ui --skill kind-ui-charts
```

The existing skill guides chart choice, public API composition and consumer checks. It is separate from repository-maintainer instructions.

</Step>
<Step>

### Retrieve the example and its contract

Use [llms.txt](/llms.txt) to find the family Markdown. On a chart page, **Copy prompt** links the exact selected source, package version, setup and family reference.

| Action | What it provides |
| --- | --- |
| Code → Copy Text | The complete component for the selected preview |
| Copy page | Page guidance, default examples and API tables |
| Copy prompt | A task brief with the selected example and verification steps |

Retrieve [Installation](/markdown/installation.md) for setup and [SeriesConfig](/markdown/chart-components/series-config.md) when defining metadata. [llms-full.txt](/llms-full.txt) is available when you need the complete set.

</Step>
<Step>

### Adapt and verify

Replace example data with the requested observations. Keep units, domains, missing-value rules and stable identities explicit. Use the installed package's public APIs; don't invent family props from another chart.

Typecheck and build the app. Check mobile layout, keyboard access, a complete data alternative and reduced motion.

</Step>
</Steps>

## A useful task

After copying a Line prompt, add your actual goal:

> Adapt this chart to weekly completed tasks. Include zero observations, preserve missing weeks as gaps, and provide a readable data table. Use our installed package version and report typecheck/build results.

The example is a starting point. Ask for missing units or data rules before making assumptions.
